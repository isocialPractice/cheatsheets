Tests

Run the suite from the repository root with node --test, no path and no glob after it.

node --test

Node finds every test file in the tree, so nothing needs changing when a test moves. Nothing has to be installed first: cases that need a browser skip with the install command as their reason.

It finds them in working folders too. Node reads no .gitignore, and its default patterns only skip a folder whose name starts with a dot - so a git-ignored folder holding something named like a test is swept along with the repository's own. Two cases in tools/test-suite-invocation.mjs watch for exactly that and name the files, because the symptom on its own is a suite that went red with nothing in the repository changed. If they fail, read what they name before reading anything else: in November 2026 it was 38 test files inside an installed browser extension, in a tool's working folder, and the fix was the tool's rather than this repository's.

The two checks the workflow runs first

node tools/build-manifest.mjs --check
node api/napkin-sketch/VENDOR-CHECK.mjs

Both run before the site publishes, so a stale manifest or an edited byte under api/napkin-sketch/ fails the deploy rather than shipping.
