Generating cheatsheets from another site

A site that already publishes code examples and explanatory sections holds everything a cheatsheet needs; node tools/cheatsheet-site.mjs <site> is what reads it.

It crawls the tree for elements carrying data-cheatsheet, collects what each one wraps, and writes a cheatsheet page per folder of the site that marked any. The output folder is resolved before anything is written - cheatsheets/ under the site root, then cheatsheets/cheatsheets/, then cheatsheets/cheatsheets_0/ and upward until a name is free - so a site that already has one of those keeps it. The script imports nothing but Node builtins, because it runs against somebody else's checkout.

A folder is a subject, so a folder is a cheatsheet

guide/install.html and guide/usage.html are written as guide.html, headed for the folder, with a section per page in the order the site reads them - each keeping the heading it asked for. A page at the site root has no folder to be named for and is written under its own name. Neither the name nor the markup depends on how many pages a folder holds, so the day a second page arrives is not the day the first page's output changes its name. Two folders of one name under different parents, or a root page named for a folder beside it, still want one file in a flat folder: that is reported and the later one is not written, rather than one being overwritten in silence.

The attribute method

The marker's value chooses the page's heading. data-cheatsheet="title" takes it from the page's own <title> and data-cheatsheet="page" from its file name; marked without a value, a page takes its title with its file name behind it. A value naming neither is reported with the page it was written on rather than quietly handed the default, as is an explicit title on a page that has none - the default has a documented fallback and the ask does not.

A heading read off a name is read as prose - somePageName.html is headed Some Page Name, and parseHTMLString.html is Parse HTML String - while a <title> is left exactly as it was written, because a file name is written for a filesystem and a title was written to be read.

The comment method

A page with more than one thing to say marks its material with a comment instead.

<!-- {% cheatsheet: [heading: page, group: page, name: splice] %} -->

It applies to the element that follows it, with nothing but whitespace in between, and carries as many properties as it needs: heading names the source the heading is read from, group says whether the page joins its folder's cheatsheet or is one of its own, and name says what file the cheatsheet is written as. A cheatsheet comment is still a comment, so a marker written inside one is still not a marker.

Which method, and what happens when they disagree

Both methods feed one collector, so a page may use either and a site may use both - and where the two speak about one heading the comment wins, because it was written about the material rather than left on an element. The disagreement is reported either way, as is a property the vocabulary does not hold or a value it does not take, with the page and the line it was written on.

Reading a run before trusting it

A run can be read before it is trusted and run twice without moving anything. --dry-run reports the folder it resolved and the pages it would write, and touches nothing. A real run records the name it resolved in cheatsheets/.../cheatsheet-site.json, and a later run reads that rather than resolving a second section beside the first - which is what it would otherwise do, because run one's output is what makes cheatsheets/ taken for run two.

The manifest carries no timestamp, so a second run over an unchanged site writes the same bytes and the generated pages can be committed and diffed. It records its own shape, and a run reads every shape the tool has written: the folder is read off where the file sits rather than out of the file, so an older manifest answers that as well as a current one and is rewritten on the way past.

Why the collector is a scanner

Having no parser available is what makes the collector a scanner, and the limits of scanning are listed in that file's own header rather than left to be discovered. A start tag is walked rather than searched, so a > inside an attribute value is not read as the end of one: <div title="a>b" data-cheatsheet> is legal HTML, is one element, and is collected as one.
