Every command reads the configuration first, so a flag on the command line is the exception rather than the way the tool is driven.

check

Reads the folder and reports. Writes nothing.

demo-app check [folder] [--quiet] [--json]

write

The same read, with the report written to outputDir. The file is named for the day it was written, so a second run on one day replaces that day's report rather than growing a folder of them. 

demo-app write ./records --out ./reports

explain

Takes one record and says what the check made of it, field by field. It is the command for the failure nobody can reproduce from the report alone. 

demo-app explain ./records/0042.json

What every command refuses

A folder that is not there, and a schema that names a type the tool has no reader for. Both are reported with the path rather than the sentence, so there is somewhere to go and look. 

demo-app check ./missing
# demo-app: ./missing is not there.
